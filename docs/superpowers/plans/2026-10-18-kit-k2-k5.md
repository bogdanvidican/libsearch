# Kit K2–K5: downloads inside the app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app downloads missing books itself (K2), shows the books that must be saved by hand plus the old kit README as Guide sections (K3), downloads encyclopedias and Khan Academy itself (K4), and picks up new book lists from GitHub without an app release (K5).

**Architecture:**
- **One downloader program** (`build/downloader/downloader.js`) runs as a child process of the server, like the indexer. It has two jobs, `books` and `zims`, which may run at the same time.
- **Progress** reaches the server over IPC and the UI through the existing `/api/status` poll.
- **Pure parts are separate modules with their own tests:** list parsers, link rules, validation, the per-topic overview.
- **Network code** is factored out of `update.ts` into `src/server/net.ts` and shared.
- **Bookkeeping lives in the library folder** (`library-search-downloads.json`), so it survives deleting or reinstalling the app. That file holds last-run failures, "done" marks, the files each scraped page or archive item produced, and the encyclopedia selection.

**Tech Stack:** TypeScript (server/downloader: Node 12 API level, esbuild `node12`; UI: React 18, ES2017), vitest, bash (kit scripts), Docker `i386/ubuntu:xenial`.

**Spec:** `docs/handoff-kit-integration.md` §4, §5, §7, §8, with Bogdan's changes of 2026-10-18 (recorded in `docs/superpowers/plans/2026-10-18-kit-k1-import.md` "Decisions" and `docs/design.md` "Download kit"):
- There is no kit folder: lists and scripts live in the app.
- `booklist-local.txt` is in the library folder.
- **Downloaded resources never live inside the app home.**

## Global Constraints

- **No downloads into the app's folder:** downloaded books, ZIMs, kiwix-tools, the user's list, logs of downloads and the bookkeeping file go in the library folder. A destination inside the app home is refused with: `"<folder>" is inside the app's folder (<app home>). Books kept there would be lost when the app is deleted or reinstalled. Choose a library folder outside the app.`
- **Server/downloader code is Node 12 compatible:** no `fs.rm`, `fs.statfs`, `AbortController`, global `fetch`, `.at()`, `Object.hasOwn`, `replaceAll`. Free space and file system type come from `df -Pk` / `stat -f -c %T` (spawned).
- **Only the server and its child processes go online.** The window stays zero-network (`src/main/main.ts` unchanged). Internet links are opened in Firefox by the server (`POST /api/open-url`), never by the window.
- **The book list format is unchanged** (`F|folder|filename|url`, `S|folder|page|regex`, `A|folder|id`; the last field is the rest of the line). BOM and CR are stripped. New list files use new type letters (`M`, `Z`), never extra fields on F/S/A.
- **Download rules match `kit/2-download-pdf-books.sh`** (handoff §4.2): the same browser User-Agent; follow redirects; `.part` + HTTP Range resume; validation (`.pdf` has `%PDF` in its first 1024 bytes, `.epub` starts with `PK`, anything else must not contain `<html`); an invalid existing file is set aside (`.bad`) and downloaded again.
- **Same scraping rules as script 2:** `&amp;`→`&`, spaces→`%20`, relative-link rules, file name = last path segment without the query with `%20`→`_` plus `.pdf` if missing, and the Hesperian sub-folder rule.
- **UI:** fits 1024×768, buttons ≥ 44 px, plain-language errors with the fix, every string in `src/ui/strings.ts`.
- **Tests:** no internet (local `127.0.0.1` servers, fake binaries on `PATH`); never `spawnSync` a process that talks to a server living in the test process.
- **Commits:** small, each ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing pushed, tagged or released.

## Decisions (executor's calls; the spec is silent or changed)

1. **Bookkeeping file:** `<first library folder>/library-search-downloads.json`. It replaces the spec's `settings.manualDone`: Bogdan's rule puts the library's state with the library. Writes are atomic (tmp + rename); a read-only library still shows the overview.
2. **Presence on the overview is a `stat` only** (exists, size > 0); the 600 small reads of a magic-byte check are too slow on the CF-30's disk. The downloader validates fully before skipping.
3. **Scrape pages (`S`) and archive.org items (`A`)** count as one item until a download has recorded which files they produce. After that they count those files, which works offline too.
4. **Free space:** books refuse to start below 500 MB free (`--min-free-mb`; 0 skips the check) and warn below 2.5 GB, as script 2 does. Encyclopedias refuse when free < remaining bytes + 1 GB.
5. **Stalls:** books give up on a file after 60 s without data (one retry for connection errors and 5xx answers). Encyclopedias retry up to 200 times, 20 s apart, resuming each time (script 4's loop).
6. **Encyclopedias download to `<name>.zim.part`** and are renamed after the ZIM magic check, so kiwix-serve never sees a half file. A partial `<name>.zim` left by script 4 is adopted as the start of the `.part`.
7. **Encyclopedia job restarts by itself:** if it was running when the app closed (`zims.resume`), it continues 30 s after the next start. Books don't auto-resume; their `.part` files resume on the next click.
8. **New list `kit/booklists/encyclopedias.txt`** (`Z|mirror dir|file prefix|approx GB|default yes/no|title`). Script 3 reads it (its `yes` items) instead of hard-coded `get` lines, so bash and the app share one list. Khan Academy's line is `no`; script 4 keeps its own Khan logic.
9. **New list `kit/booklists/manual-downloads.txt`** (`M|folder|title|url|how|note`). A test keeps the kit README's manual checklist and this file in sync.
10. **K5 list updates:** fetched from `https://raw.githubusercontent.com/<repo>/HEAD/kit/booklists/<file>` with the update-check schedule, covered by the same "Update automatically" switch. They're cached in `<data dir>/booklists/` and used only by the app version that fetched them, and only if they parse and have at least half the bundled entries. The bash scripts keep using the lists that came with the app.
11. **Version:** one bump to 0.5.0 at the end; the intermediate milestones are never released on their own.
12. **Reviews:** a fresh whole-branch review after K2 and another after K5 (the diff is too large for one).

## Review Focus

1. **The app closes or the laptop sleeps in the middle of a 168 GB download:** the next start continues from the bytes already on disk, never from zero, and never leaves a `.zim` that kiwix-serve chokes on. Covered in Tasks 14 and 16.
2. **A site answers 200 with an HTML bot-check page, 202 with nothing, or 403:** the book is listed as failed with a plain reason and an Open in Firefox button, no junk file stays behind, and a valid book already on disk is never destroyed. Covered in Tasks 3 and 4.
3. **The library folder is unplugged, read-only, full, or inside the app:** the page says so plainly and nothing is written elsewhere. Covered in Tasks 4, 6 and 7.
4. **Offline:** Get books and Encyclopedias still show what is there and what is missing, and saying "needs internet" is the only failure. Covered in Tasks 6, 8 and 16.
5. **A list fetched from GitHub that is truncated or garbled:** the app keeps the lists it came with. Covered in Task 18.

### Task 2: Book lists, link rules, file validation (pure)

**Files:** Create `src/downloader/booklist.ts`, `src/downloader/links.ts`, `src/downloader/validate.ts`; tests `tests/downloader/booklist.test.ts`, `links.test.ts`, `validate.test.ts`.

**Produces:**
- `type ListEntry = { type: 'F'|'S'|'A'; folder: string; a: string; b: string; source: string; line: number }`:
  - F: `a` = filename, `b` = url.
  - S: `a` = page, `b` = regex.
  - A: `a` = archive.org id, `b` = ''.
- `parseBookList(text: string, source: string): { entries: ListEntry[]; problems: string[] }`:

- `resolveLink(page: string, link: string): string`: an exact port of script 2's `resolve()`.

- `fileNameFromUrl(url: string): string`.
- `scrapeFolder(folder, page, url)`: the Hesperian rule (page contains `hesperian` → `folder/<parent segment>`).
- `archivePdfNames(metadataJson: string): string[]`: `files[].name` ending `.pdf`, minus `_text.pdf`.
- `isValidContent(fileName: string, head: Buffer): boolean` and `isValidFile(path): boolean` (reads ≤ 1024 bytes).

- [ ] **Tests:**

### Task 4: The books job

**Files:** Create `src/downloader/state.ts`, `src/downloader/disk.ts`, `src/downloader/books.ts`; modify `src/shared/api.ts` (`DownloadProgress`, `DownloadFailure`); test `tests/downloader/books.test.ts`.

**Produces:**
- **`api.ts` types:**
  - `DownloadProgress { running; phase: 'idle'|'checking'|'downloading'|'done'|'failed'|'cancelled'; done; total; currentFile; fileReceived; fileTotal; bytes; speed; downloaded; skipped; failed; attempt?; startedAt?; finishedAt?; notice? }`
  - `DownloadFailure { id; folder; file; url; code; reason; at }`
- **`state.ts`:**
  - `STATE_FILE = 'library-search-downloads.json'`.
  - `LibraryState { version: 1; books: { lastRun?: { startedAt; finishedAt; downloaded; skipped; failed }; failures: DownloadFailure[]; collections: Record<string, string[]>; done: string[] }; manualDone: string[]; zims: { selected: string[]; resume: boolean } }`
  - `loadState(root): LibraryState` (defaults on missing or broken) and `updateState(root, fn: (s) => void): LibraryState`.
- **`disk.ts`:** `freeBytes(dir): number | undefined` (`df -Pk`) and `fsType(dir): string | undefined` (`stat -f -c %T`, Linux only).
- **`books.ts`:** `downloadBooks(o: { library: string; lists: string[]; checkUrl: string; archiveBase: string; minFreeMb: number; stallMs: number; userAgent?: string }, h: { onProgress(p: DownloadProgress): void; isCancelled(): boolean; log(line: string): void }): Promise<DownloadProgress>`. In order:
  1. **Pre-check:** GET `checkUrl`. Offline → phase `failed` with notice code `downloads-offline`.
  2. **Free space:** below `minFreeMb` → `downloads-disk-full`.
  3. **Parse the lists.**
  4. **F entries:** skip when valid; set an invalid file aside as `.bad` and download again; validate the `.part` before renaming.
  5. **S/A entries:** scrape or read metadata, then fetch each file. Record `collections[entryId]` (paths relative to the library). An unreadable page or one with no links becomes a failure with file `(page)`, as bash records it.
  6. **Afterwards:** write `books.lastRun` and `books.failures`.
  7. **Cancel:** stop at once and return phase `cancelled`; `.part` files stay.
  8. **Speed** is computed over the last 5 s.
- [ ] **Tests (local server, temp library named `Library & Co (test)`):**
  - `it('downloads F, S (with Hesperian sub-folders) and A entries into the library')`
  - `it('skips books that are already there and valid, without a request')`
  - `it('sets an HTML file named .pdf aside, downloads it again, and keeps a valid book when the new download fails')`: the old invalid file is removed, as bash does; a *valid* existing file is never touched.
  - `it('records 403, 202-empty, bot-check HTML and empty scrape pages as failures with reasons')`
  - `it('says "offline" when the check address can't be reached, and downloads nothing')`
  - `it('refuses to start when the disk is too full')`: `minFreeMb` huge.
  - `it('stops on cancel and the next run resumes the .part')`
  - `it('remembers which files a page or archive item produced')`

### Task 14: Downloading a ZIM

**Files:** Create `src/downloader/zims.ts`; test `tests/downloader/zims.test.ts`.

**Consumes:** `fetchToFile` (Task 3), `inspectZim` / `ZIM_MAGIC` (`src/server/kiwix.ts`), `freeBytes` / `fsType` (Task 4).

**Produces:** `downloadZims(o: { kiwixDir: string; entries: ZimEntry[]; mirror: string; retries: number; retryDelayMs: number; stallMs: number; minFreeMb: number; skipFsCheck?: boolean }, h): Promise<DownloadProgress>`. For each entry:
1. Find the newest file (mirror listing) and its size (GET with `Range: bytes=0-0` → `Content-Range`, or `Content-Length`).
2. Skip it when `<file>.zim` is complete (size matches and the magic is right).
3. Adopt a partial `<file>.zim` from script 4 as the `.part`.
4. FAT32 (`msdos`/`vfat`) with a size ≥ 4 GiB → failed with a reason.
5. Not enough free space → failed with a reason.
6. Resume loop: up to `retries` tries, `retryDelayMs` apart, each resuming.
7. Check the magic `5A 49 4D 04`, rename, and send `zim-done`.

Older files with the same prefix are left alone; the overview shows them as old.
