# Kit K1: download scripts and book lists live in the app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Download scripts 1-5, the book lists and the kit guide live in the app (`kit/`) and ship with every release. There is no separate kit folder any more. The scripts work on the user's library folder, and the user's own list `booklist-local.txt` lives in that library folder.

**Architecture:** The files are imported into `kit/` and `kit/booklists/` (packaged at `resources/app/kit/`; `scripts/package.mjs` already stages `kit/` recursively). Scripts 2-5 stop working on "the folder I'm in" and pick the library folder instead, via a small sourced helper `kit/library-folder.sh`. The installer stops copying anything into a kit folder.

**Tech Stack:** bash (Ubuntu 16.04: bash 4.3, GNU coreutils, curl 7.47), vitest, Docker `i386/ubuntu:xenial`.

**Spec:** `docs/handoff-kit-integration.md` (milestone K1, sections 2, 3, 4.1, 6, 7, 8) as changed by Bogdan on 2026-10-18:
- No separate kit folder: everything is in the app.
- `booklist-local.txt` lives in the library folder.
- The bash scripts stay as a fallback and read the same lists as the app.
- Old kit files on existing machines are left alone; the release notes say to delete them once.

Constraints: `HANDOFF.md` §2, `docs/design.md`.

## Global Constraints

- **Downloaded resources never live inside the app.** Books, encyclopedias, `kiwix-tools`, `booklist-local.txt` and the download logs all go in the library folder, which must be outside the app home (the folder holding `dist/`, or the git checkout). Deleting or reinstalling the app must leave them. The app may sit inside the library (`<library>/library-search-app`), never the other way round.
- Bash must run on bash 4.3 + GNU coreutils + curl 7.47. The vitest suite also runs it with macOS `/bin/bash` 3.2 + BSD tools, so: no `mapfile`/`readarray`, no `declare -A`, no `${v,,}`, and `sed -i` only on Linux-only paths.
- Book list line format is unchanged: `F|folder|filename|url`, `S|folder|page-url|regex`, `A|folder|archive.org-id`. The last field is the rest of the line (bash `read -r t a b c`). Never add fields.
- Paths contain spaces, `&`, `(`, `)` and `,` (`Community Rebuild Library`, `02 Water & Sanitation`). Quote every expansion.
- `.sh` files: mode 100755 in git. The README and lists: 100644.
- Tests make no internet calls (local `127.0.0.1` servers only; a fake `curl`/`firefox` on `PATH` where a script would go online). No PDFs in the repo. No Python added.
- Small commits, each ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed, tagged or released without Bogdan's OK.

## Decisions

1. **Library folder rule** for scripts 2-5:
   - The first argument, when it is an existing folder.
   - Otherwise the current folder, when it already holds a `NN Name` folder (the same rule the app uses to auto-detect a library).
   - Otherwise the script explains how to name the folder and stops.
   - It refuses the app home and anything inside it. The app home is `${KIT_DIR%%/dist/library-search-*}` for a package, or `$KIT_DIR/..` when that holds a `package.json` with `"name": "library-search"` (a git checkout). Unknown layout: only `$KIT_DIR` itself is refused. Paths are compared after `cd … && pwd -P`, so symlinks can't sneak past.
2. **The lists come from the app:** `<kit dir>/booklists/booklist-main.txt` and `booklist-linux.txt`, plus `<library>/booklist-local.txt`. Script 2 creates `booklist-local.txt` from `kit/booklists/booklist-local-template.txt` when it is missing.
3. **The 1-5 `.desktop` launchers are not imported, and `kit/6-search-the-library.desktop` is deleted.** Nobody browses the app's folder, and with no library folder given these launchers could only fail. The app's menu entry is generated by the installer and stays.
4. **The installer no longer copies files into a kit folder.** `--kit <folder>` is still accepted and ignored, so older instructions don't break. The summary prints where the download scripts are.
5. **Script 2 gets one test hook:** `LIBRARY_KIT_CHECK_URL` (default `https://www.gutenberg.org/`) for its internet pre-check.
6. **`kit/README-section.md` is deleted.** The imported kit README already contains every line of it (checked).

## Review Focus

1. **`booklist-local.txt` saved without a final newline, or with CRLF line ends** (gedit, Notepad): its last book must still be read, and must not glue onto another list's line. Covered in Task 2.
2. **A library path and book folders with spaces, `&`, parentheses and commas, and URLs with `(`, `)`, `&`, `%20`, `?`:** downloads land in the right place. Covered in Tasks 2 and 4.
3. **A script started with no folder, from a folder that isn't a library** (home, the app's own `kit/`): it explains and creates nothing. **An explicit folder anywhere inside the app home** (e.g. `~/library-search/books`) is refused, while the app home's parent (a library holding the app) is accepted. Covered in Task 2.
4. **`bash 4-download-khan-academy.sh es` run inside the library:** `es` is the language, not a folder. With `bash 4-download-khan-academy.sh "<library>" es` it gets both. Covered in Task 2.
5. **The installer run on today's CF-30, where an old kit folder holds copies of `6-*`, lists and the README:** it changes none of them. Covered in Task 3.
